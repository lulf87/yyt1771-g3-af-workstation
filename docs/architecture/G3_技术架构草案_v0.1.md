# G3 技术架构草案 v0.1

## 1. 总体架构

```text
frontend: Vite + React + TypeScript
backend: FastAPI + Python 3.11+
vision: pure Python / OpenCV / NumPy
services: setup / playback / run / analysis / export
storage: project / run / artifact / manifest
device adapters: camera / temperature lazy import
```

## 4. 坐标边界

```text
前端显示坐标：只用于渲染和鼠标交互。
measurement coordinates：正式 ROI、A/B、distance 的唯一坐标体系。
默认 measurement coordinates：原始图像 pixel 坐标。
```

前端必须把显示坐标映射到 measurement coordinates 后提交给后端。

---

## 5. 服务边界

```text
API layer：薄层，只做请求/响应。
Service layer：业务流程。
Vision layer：纯算法。
Storage layer：读写 artifact。
Camera/temperature adapters：设备隔离，lazy import。
```

---

## 6. 关键设计约束

```text
前端不计算正式 A/B / distance。
Detector 不依赖浏览器显示坐标。
无相机也可运行 offline/playback。
历史 run 不被 re-analysis 覆盖。
```

---

## 7. 多检测位置增量兼容架构

```text
MeasurementDefinition.regions（权威，1–6 个）
  -> 每帧只采集一次图像
  -> 每帧只读取一次温度
  -> region_detection_service 按 enabled region 裁剪 ROI 并独立检测
  -> candidate / temporal / policy / outlier / curve 状态全部按 region_id 隔离
  -> frame event.region_results
  -> RunManifest.region_detection_results
  -> AnalysisResult.regions（逐位置 AFAS）
  -> long / wide / per-region / combined export
```

旧接口保留第二层兼容镜像：`measurement.roi`、frame event 顶层 `detection_result/curve_points/live_point_status`、`RunManifest.detection_results` 和 `AnalysisResult` 顶层曲线/AFAS 字段均代表第一个启用位置。旧 manifest/export/import 在边界层规范化为 `region_1`，核心流程不再依赖“固定六个字段”。

前端位置配置使用 `MeasurementRegion[]`，实时状态与曲线使用以 `region_id` 为键的 map。产品 UI 固定 Operator，强制 `contrast_widest_span` 并只暴露共享对比度阈值、最大跳变与位置/ROI 控件；既有 Engineering 组件仅作为未挂载的兼容代码保留，不从正常入口访问。

## 8. 启动期运行来源策略

正常产品入口固定为 Operator。后端启动时把 `YYT1771_G3_RUNTIME_SOURCE=real_hardware|simulated_material` 和 `YYT1771_G3_PRODUCT_MODE=production|development` 解析为不可由浏览器修改的 `RuntimePolicy`。`/api/app/runtime` 提供只读显示信息，Probe/Run guard 阻止跨来源调用。真实模式不 fallback 到模拟设备；模拟模式使用启动时指定的 dataset id，并复用相同的 1–6 ROI 实际使用流程。

## 9. Operator run v2 持久化与停止流程

Operator 新运行使用轻量 v2 存储：

```text
runs/<run_id>/
  run_meta.json          运行、来源、ROI 和参数快照
  run_state.json         RUNNING/STOP_REQUESTED/FINALIZING/READY/ERROR
  results.sqlite         唯一一份逐帧、逐 ROI 正式结果
  analysis_summary.json  结果页曲线与 AFAS 显示快照
```

`results.sqlite` 在运行期间分批提交；停止后只提交尾批次、计算各 ROI 最终分析并原子写入 summary。流式 `complete` 事件只返回 `run_id` 和状态，结果页从 `/api/runs/{run_id}/summary` 读取轻量快照，详细结果通过分页或单帧接口读取。停止超时不得重新调用 detector。

Engineering 和旧历史 run 继续使用 v1 读取路径；新 v2 run 只在用户显式点击导出时才按需生成 CSV/JSON/PNG/ZIP 兼容产物。
