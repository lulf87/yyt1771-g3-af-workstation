# YY/T 1771 AF Web Station G3 需求规格说明书 v0.1

版本：v0.1  
日期：2026-06-03  
状态：需求基线草案，已确认核心方向  
项目简称：G3

---

## 0. 文档目的

本文档用于定义第三代 YY/T 1771 风格 AF 视觉测量系统的核心需求。

G3 不是对一代 `yyt1771_starter` 或二代 `yyt1771-af-web-station` 的简单修补，而是在吸收两代经验的基础上重新明确以下问题：

```text
什么是待测物体
什么是整体外包络
什么是正式 A/B 点
什么是有效 distance
什么数据可以进入 temperature-distance 曲线
什么数据只作为诊断信息保存
```

G3 的首要目标是稳定识别 ROI 内的待测物体整体外包络，并从该整体外包络上提取稳定、可复现的 A/B 点和 pixel distance。

---

## 1. 项目背景

G3 基于以下两个历史项目经验重新设计：

```text
yyt1771_starter：一代系统，功能较完整，但架构和算法复杂度较高。
yyt1771-af-web-station：二代系统，Web + Python 架构更清晰，但 A/B 稳定性仍未完全解决。
```

当前长期未解决的关键问题主要集中在：

```text
1. A/B 点跳动。
2. 系统误把内部缝隙、暗线、纹理或局部细支边界当作正式边界。
3. 多细支 / 多线束目标未被稳定识别为一个整体。
4. ROI、显示坐标、正式计算坐标之间容易混乱。
5. 仍可能存在其他隐藏问题，需要通过 G3 的诊断与回放能力暴露。
```

本系统用于 YY/T 1771 风格的奥氏体 Af 点检测流程。业务关注点是：

```text
在升温过程中，持续记录待测物体形变趋势。
形变趋势用 A/B distance_px 表示。
最终形成 temperature-distance 曲线，用于后续 Af 判断。
```

---

## 2. 第一阶段目标优先级

G3 第一阶段目标优先级按以下顺序确定：

```text
A. 先解决真实离线帧中的 A/B 稳定性。
E. 建立算法验证平台。
B. 接入真实相机 live run。
C. 完整 Web 工作站流程。
D. 报告和导出。
```

核心判断：

> 当前最大问题不是前端显示，也不是报告格式，而是系统必须先稳定识别 ROI 内的待测物体整体外包络。只有外包络定义稳定，A/B 点和 distance 曲线才有意义。

---

## 3. 核心测量原则

G3 的正式测量原则如下：

```text
1. 操作者在图像上框选一个 rotated ROI。
2. ROI 内只包含有效测量主体，不包含夹具、底座、连接丝、焊点等非测量结构。
3. 系统先识别待测物体整体外包络。
4. A/B 点只能来自整体外包络。
5. 内部白色缝隙、内部暗线、纹理、交叉线、单根细支边界都不能作为正式 A/B。
6. 外部 speck、小黑点、灰尘不能被识别为待测物体。
7. 对 A/C 类对象，正式 distance 是整体外包络的最大宽度。
8. distance 单位为 pixel。
9. 系统目标是得到 distance 随 temperature 变化的趋势曲线，用于后续 Af 判断。
```

---

## 4. 检测对象分类

G3 第一阶段支持三类对象。

| 类别 | 名称 | 当前状态 | 宽度模式 | 第一阶段要求 |
|---|---|---|---|---|
| A | 球囊 / 网状支架类 | 已有图像样例 | max-width | 必须实现 |
| C | 多细支 / 多线束整体类 | 已有图像样例 | max-width | 必须实现 |
| D | 管体 / 其他待定义对象 | 暂无实物 | max-width 或 min-width 均可能 | 预留接口，不定义具体算法 |

已确认决策：

```text
A/C 仅适用 max-width。
D 未来可能需要 max-width，也可能需要 min-width。
默认模式为 max-width。
```

## 5. A/B 点正式定义

### 5.1 A/C 类对象定义

对 A 类球囊 / 网状支架对象、C 类多细支 / 多线束对象，A/B 点定义为：

```text
在 ROI 内，系统识别目标整体外包络。
沿垂直于 ROI 主方向的测量轴扫描目标宽度。
找到整体外包络宽度最大的测量轴。
该测量轴与目标整体外包络的两个外侧接触点，即为正式 A/B 点。
distance_px = A 点与 B 点之间的欧氏距离。
```

简化表达：

```text
正式 A/B = ROI 内目标整体外包络最大宽度位置的两个外侧接触点。
```

### 5.2 测量方向

已确认：

```text
ROI 主方向 = 待测物体长度方向 / 展开方向。
A/B 测量轴 = 垂直于 ROI 主方向。
distance = 目标整体外包络在该测量轴上的宽度。
```

### 5.3 禁止作为正式 A/B 的内容

以下内容不能作为正式 A/B：

```text
内部白色缝隙
内部暗线
内部纹理
高光
交叉线
单根细支边界
物体外 speck / 小黑点
灰尘
夹具
连接丝
焊点
底部固定片
非 ROI 内结构
```

## 6. 整体外包络定义

G3 不使用简单纯凸包作为正式外包络。

已确认的整体外包络原则为：

```text
整体外包络可以跨过内部缝隙，
但不能无脑把明显外部空白区域也算进目标。
```

也就是说，系统需要识别的是：

```text
object body mask / envelope mask
```

而不是简单的：

```text
convex hull
```

### 6.1 A 类对象外包络规则

A 类对象是球囊 / 网状支架类结构。

规则：

```text
1. 网状结构整体作为待测主体。
2. 网眼内部空白视为目标内部结构，不参与边界判断。
3. 外包络应沿网状主体外侧形成连续边界。
4. 只测 ROI 内有效主体。
5. 底部连接丝、夹持片、焊点不参与测量。
6. A 类不识别内部网格作为正式边界；内部网格只用于证明主体存在。
7. 推荐算法为白底暗线增强、滞后阈值、主体连通域筛选、稳定行窗口或测量轴窗口左右外包络提取。
8. outer_contour_debug / filled_contour_debug 可作为诊断输出，但正式 distance_px 不强制依赖完整闭合实心轮廓。
9. 夹子、连接丝、支撑丝、窄尾即使进入 ROI，也不得决定正式 max-width A/B。
```

### 6.2 C 类对象外包络规则

C 类对象是多细支 / 多线束整体结构。

规则：

```text
1. 多根细支视为一个整体目标。
2. 相邻细支之间的白色间隙视为目标内部。
3. 不允许检测单根细支宽度。
4. 不允许将内部暗线、交叉线、细支边缘作为正式 A/B。
5. 正式 A/B 必须来自多细支整体外包络。
6. 测试过程中细支会逐渐松开，系统需要持续监测每帧整体外包络最大宽度。
```

```text
质量状态输出
```

### 7.2 BundleEnvelopeDetector

用于 C 类多细支 / 多线束对象。


## 8. ROI 规则

### 8.1 ROI 类型

```text
检测位置数量：最少 1 个，最多 6 个；默认 1 个。
每个检测位置拥有独立 rotated ROI；未启用位置保留配置，但不检测、不生成正式曲线、不导出正式数据。
ROI 类型：rotated ROI。
ROI 操作方式：操作者在 Web UI 上用鼠标拖拽。
ROI 角度：通过拖拽产生，不要求手动输入角度。
ROI 范围：只框有效测量主体。
```

### 8.2 检测位置与运行锁定

```text
用户可在测试开始前添加、删除、启用、禁用、重命名检测位置，并选择当前编辑位置。
删除后显示顺序可重排，但 region_id 和 color 对仍存位置保持稳定。
至少保留 1 个位置且至少 1 个位置启用；最多配置 6 个位置。
测试开始后，本次 run 的 regions 快照锁定，运行中不可新增、删除、启用、禁用或修改 ROI。
同一帧图像只采集一次、温度只读取一次；所有启用位置共享该帧和温度，并分别执行检测。
每个位置独立维护检测结果、异常点过滤状态、正式 temperature-distance 曲线和 AFAS 分析结果。
```

### 8.3 ROI 坐标系统

正式需求写法：

> 系统必须使用统一、稳定、可复现的 measurement coordinates 进行正式测量。默认 measurement coordinates 为原始图像 pixel 坐标。前端可以缩放显示图像，但缩放只影响显示，不影响正式 ROI、A/B、distance 计算。

也就是说：

```text
操作者看到的是浏览器显示图。
系统内部保存的是 measurement coordinates 下的 ROI。
A/B 点和 distance_px 都在 measurement coordinates 中计算。
```

这样做的原因不是因为 Af 测试必须使用原始坐标，而是为了保证：

```text
同一组数据，
同一套 ROI，
同一套参数，
在不同电脑、不同浏览器窗口、不同缩放比例下，
得到完全一致的 distance 曲线。
```

### 8.3 ROI 与参数联动

当用户修改以下任一内容时，应重新检测当前 ROI 内物体：

```text
ROI
detector 类型
max/min-width mode
threshold
morphology 参数
jump limit
其他 detector 参数
```

### 8.4 Run 配置快照

每次正式 run 开始时，系统必须保存当时的：

```text
ROI
detector 类型
width mode
全部 detector 参数
温控参数
相机参数
软件配置
```

后续用户修改 ROI 或参数，不覆盖旧 run。

## 9. Measurement Coordinates 与趋势曲线

G3 的业务目标是得到：

```text
temperature - distance_px 曲线
```

而不是得到绝对物理尺寸。

因此：

```text
distance_px 可以是相对像素值。
不需要 mm 换算。
不需要标定板。
不需要 pixel-to-mm calibration。
```

但必须保证：

```text
distance_px 的坐标尺度在一次 run 内保持一致。
同一数据集重复分析结果必须一致。
同一帧不能因为前端缩放不同而得到不同 distance。
```

所以系统内部默认使用原始图像 pixel 坐标作为 measurement coordinates。

## 10. A/B 稳定性策略

G3 不简单使用“最大跳动阈值”限制真实变化。

因为真实测试中，待测物体可能真的在变形，A/B 位置和 distance 都可能发生变化。

真正需要解决的是：

```text
多个候选位置宽度相同或非常接近时，
A/B 点在几个候选位置之间来回跳。
```

### 10.1 候选选择规则

每帧检测时保存两类候选：

```text
raw_best_candidate
selected_candidate
```

含义：

```text
raw_best_candidate：
    本帧纯按宽度最大原则得到的候选。

selected_candidate：
    经过时间连续性稳定策略后，正式用于 distance 曲线的候选。
```

### 10.2 Tie-break 策略

当多个候选宽度接近时：

```text
1. 找出本帧所有合法候选。
2. 找出 raw_best_width。
3. 若多个候选与 raw_best_width 的差值 <= tie_width_epsilon_px，则视为宽度等价。
4. 在宽度等价候选中，优先选择离上一帧 selected_candidate 最近的候选。
5. 只有当新候选明显更宽，或连续 N 帧更优，才允许切换位置。
```

### 10.3 Invalid 优先原则

G3 遇到异常帧时：

```text
宁可输出 INVALID，
也不要输出看似正常但实际错误的 A/B。
```

异常情况包括：

```text
外包络不可信
候选跳变过大
目标连通性异常
A/B 点落在内部结构
A/B 点落在外部 speck
A/B 点落在夹具或连接丝
ROI 内目标缺失
质量评分不足
温度同步不可用于 Af 分析
```

## 12. 温度同步需求

G3 需要真实温控仪 / PLC。

运行模式包括：

```text
Offline playback
Live offline run
Real camera run
```

都需要能把以下数据对应起来：

```text
frame
timestamp
temperature
distance
```

### 12.1 温度同步目标

```text
图像帧时间戳与温度时间戳误差目标：<= 10 ms。
```

每帧保存：

```text
frame_timestamp_ms
temperature_timestamp_ms
temperature_celsius
temperature_delta_ms
temperature_source
temperature_sampled_this_frame
temperature_sync_status
```

### 12.2 温度状态

```text
TEMP_SYNC_OK：
    |frame_timestamp_ms - temperature_timestamp_ms| <= 10 ms。

TEMP_SYNC_INTERPOLATED：
    使用前后温度采样点插值得到该帧温度。

TEMP_SYNC_STALE：
    温度值复用了旧采样，且时间误差 > 10 ms。

TEMP_SYNC_MISSING：
    没有温度数据。
```

### 12.3 温度异常帧处理

已确认采用 A + C：

```text
A/B 检测结果仍保存。
Af 计算和 temperature-distance 曲线只使用 TEMP_SYNC_OK 或 TEMP_SYNC_INTERPOLATED 的点。
```

不因为温度 stale 就丢弃图像检测结果，但 stale 点不能进入正式 Af 分析。

## 13. 运行模式

G3 支持以下运行模式。

| 模式 | 是否需要 | 说明 |
|---|---|---|
| Offline playback | 是 | 读取真实离线帧，逐帧查看 |
| Live offline run | 是 | 把离线帧当作相机流运行 |
| Re-analysis | 是 | 对历史 run 或离线数据重新分析 |
| Real camera preview | 是 | 真实相机实时预览 |
| Real camera run | 是 | 真实相机正式采集、测量、记录 |
| Mock mode | 不作为操作员流程 | 可作为内部开发测试 fixture |

### 13.1 建议开发顺序

```text
1. Offline playback
2. Live offline run
3. Re-analysis
4. Real camera preview
5. Real camera run
6. Analysis / Export
```

## 20. Re-analysis 规则

G3 支持 re-analysis。

规则：

```text
1. 历史 run 的原始输入和原始结果不覆盖。
2. 使用新 ROI、新 detector 或新参数重新分析时，生成新的 analysis version。
3. 每个 analysis version 保存自己的配置快照。
4. 同一数据、同一配置、同一代码版本，重复运行结果必须完全一致。
```

## 23. 当前已锁定的关键决策

```text
A/C = max-width。
D = 预留 max-width 或 min-width。
A/B = 整体外包络最大宽度处两个外侧接触点。
检测位置 = 默认 1 个、最少 1 个、最多 6 个；每个位置一个 rotated ROI。
region_1 = 旧单 ROI 兼容位置；顶层 roi / DetectionResult / AnalysisResult 字段镜像第一个启用位置。
ROI 坐标 = 统一 measurement coordinates，默认原图 pixel。
distance = pixel only。
核心目标 = temperature-distance trend。
外包络 = 可跨内部缝隙，但不是纯凸包。
A 类外包络 = 暗线增强后的网状主体左右整体外包络；正式测宽不依赖内部网格或完整闭合实心轮廓。
内部缝隙/纹理/暗线 = 忽略。
多细支 = 整体目标。
外部 speck = 排除，不能识别为目标。
异常帧 = INVALID 优先，不输出错误 A/B。
温度同步 >10ms = A/B 保存，Af 曲线只用 OK/interpolated 点。
导出 = CSV / JSON / PNG。
```

## 26. 术语表

| 术语 | 含义 |
|---|---|
| Measurement Position / MeasurementRegion | 一套稳定 `region_id`、显示顺序、名称、启用状态、颜色和 rotated ROI；每次测量允许 1–6 个。 |
| ROI | 某一检测位置的用户框选待测区域；所有 ROI 均使用 measurement coordinates。 |
| measurement coordinates | G3 正式计算使用的统一坐标系，默认等于原始图像 pixel 坐标。 |
| A/B 点 | 整体外包络最大宽度位置的两个外侧接触点。 |
| distance_px | A/B 两点之间的欧氏像素距离。 |
| outer envelope / 整体外包络 | 跨过内部缝隙但不包含明显外部空白的目标整体边界。 |
| raw_best_candidate | 本帧纯按宽度最大原则得到的候选。 |
| selected_candidate | 经过时间连续性稳定策略后用于正式曲线的候选。 |
| TEMP_SYNC_OK | 温度与图像时间戳误差 <= 10ms。 |
| TEMP_SYNC_INTERPOLATED | 用前后温度采样点插值得到的温度。 |
| TEMP_SYNC_STALE | 温度复用了旧采样且时间误差 >10ms。 |
| INVALID | 当前帧检测不可作为正式结果。 |

---

## 27. 结论

G3 的核心需求可以总结为：

> 系统通过 Web UI 选择单个 rotated ROI，在统一 measurement coordinates 中识别 ROI 内待测物体的整体外包络，并从整体外包络上提取 A/C 类对象的 max-width A/B 点，持续输出 distance_px 与 temperature 对应关系。系统必须保证内部缝隙、纹理、暗线、单根细支、外部 speck、夹具和非测量结构不会成为正式 A/B。异常帧优先输出 INVALID，不输出错误距离。temperature-distance 曲线只使用温度同步 OK 或可插值的数据点。
