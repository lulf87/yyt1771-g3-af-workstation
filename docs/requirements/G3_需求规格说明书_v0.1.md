# YY/T 1771 AF Web Station G3 需求规格说明书 v0.1

版本：v0.1  
日期：2026-06-03  
状态：需求基线草案，已确认核心方向  
项目简称：G3

2026-07-15 需求变更：当前产品取消 A/C/D 业务分类，统一为 `WHOLE_ENVELOPE` 整体外包络测量；旧分类和 detector 名称只保留历史兼容。ROI 正式定义为可旋转窄测量带，新建默认高度为 8 px。

---

## 0. 文档目的

本文档用于定义第三代 YY/T 1771 风格 AF 视觉测量系统的核心需求。

G3 不是对一代 `yyt1771_starter` 或二代 `yyt1771-af-web-station` 的简单修补，而是在吸收两代经验的基础上重新明确以下问题：

```text
什么是待测物体
什么是整体外包络
什么是正式 A/B 点
什么是有效 distance
什么数据可以进入 temperature-distance 曲线
什么数据只作为诊断信息保存
```

G3 的首要目标是稳定识别 ROI 内的待测物体整体外包络，并从该整体外包络上提取稳定、可复现的 A/B 点和 pixel distance。

---

## 1. 项目背景

G3 基于以下两个历史项目经验重新设计：

```text
yyt1771_starter：一代系统，功能较完整，但架构和算法复杂度较高。
yyt1771-af-web-station：二代系统，Web + Python 架构更清晰，但 A/B 稳定性仍未完全解决。
```

当前长期未解决的关键问题主要集中在：

```text
1. A/B 点跳动。
2. 系统误把内部缝隙、暗线、纹理或局部细支边界当作正式边界。
3. 多细支 / 多线束目标未被稳定识别为一个整体。
4. ROI、显示坐标、正式计算坐标之间容易混乱。
5. 仍可能存在其他隐藏问题，需要通过 G3 的诊断与回放能力暴露。
```

本系统用于 YY/T 1771 风格的奥氏体 Af 点检测流程。业务关注点是：

```text
在升温过程中，持续记录待测物体形变趋势。
形变趋势用 A/B distance_px 表示。
最终形成 temperature-distance 曲线，用于后续 Af 判断。
```

---

## 2. 第一阶段目标优先级

G3 第一阶段目标优先级按以下顺序确定：

```text
A. 先解决真实离线帧中的 A/B 稳定性。
E. 建立算法验证平台。
B. 接入真实相机 live run。
C. 完整 Web 工作站流程。
D. 报告和导出。
```

核心判断：

> 当前最大问题不是前端显示，也不是报告格式，而是系统必须先稳定识别 ROI 内的待测物体整体外包络。只有外包络定义稳定，A/B 点和 distance 曲线才有意义。

---

## 3. 核心测量原则

G3 的正式测量原则如下：

```text
1. 操作者在图像上放置一个可旋转窄测量带（数据结构仍为非零高度 rotated ROI）。
2. 测量带内只包含有效测量主体，不包含夹具、底座、连接丝、焊点等非测量结构。
3. 系统先识别待测物体整体外包络。
4. A/B 点只能来自整体外包络。
5. 内部白色缝隙、内部暗线、纹理、交叉线、单根细支边界都不能作为正式 A/B。
6. 外部 speck、小黑点、灰尘不能被识别为待测物体。
7. 正式 distance 是同一有效扫描行上整体外包络沿测量带局部宽度轴的最大外侧跨度。
8. distance 单位为 pixel。
9. 系统目标是得到 distance 随 temperature 变化的趋势曲线，用于后续 Af 判断。
```

## 4. 统一测量模型

G3 当前只有一个正式业务模型：

| 当前模型 | 名称 | detector | width mode | 状态 |
|---|---|---|---|---|
| WHOLE_ENVELOPE | 整体外包络测量 | ContrastWidestSpanDetector | max_width | 唯一正式模型 |

```text
当前界面不再询问或显示 A/C/D 对象类别。
新建测量固定为 WHOLE_ENVELOPE + ContrastWidestSpanDetector + max_width。
A_BALLOON_ENVELOPE、C_BUNDLE_ENVELOPE、D_RESERVED_OBJECT 及旧 Balloon/Bundle detector 仅用于历史 run、旧导出和 Golden 回归兼容。
历史数据按原值解析和显示，不静默重写；旧值不得重新成为当前产品选项或默认值。
```

## 5. A/B 点正式定义

### 5.1 整体外包络 A/B 定义

```text
在窄测量带内，系统依据亮暗对比阈值识别目标支持。
沿 rotated ROI 的局部宽度轴（u 轴）逐行扫描目标跨度。
在有效扫描行中找到整体外包络外侧跨度最大的同一行。
该行上目标整体外包络的两个最外侧接触点，即为正式 A/B 点。
distance_px = A 点与 B 点之间的欧氏距离。
```

简化表达：

```text
正式 A/B = 窄测量带内同一有效扫描行上目标整体外包络的两个最外侧接触点。
```

### 5.2 测量方向

已确认：

```text
rotated ROI 局部宽度轴（u 轴）= A/B 测量轴。
rotated ROI 高度 = 该测量轴周围的采样带宽。
distance = 目标整体外包络在 u 轴上的外侧跨度。
不得把不同扫描行的左、右端点拼接成正式 A/B。
```

### 5.3 禁止作为正式 A/B 的内容

以下内容不能作为正式 A/B：

```text
内部白色缝隙
内部暗线
内部纹理
高光
交叉线
单根细支边界
物体外 speck / 小黑点
灰尘
夹具
连接丝
焊点
底部固定片
非 ROI 内结构
```

## 6. 整体外包络定义

G3 不使用简单纯凸包作为正式外包络。

已确认的整体外包络原则为：

```text
整体外包络可以跨过内部缝隙，
但不能无脑把明显外部空白区域也算进目标。
```

也就是说，系统需要识别的是：

```text
object body mask / envelope mask
```

而不是简单的：

```text
convex hull
```

### 6.1 统一外包络规则

```text
1. 窄测量带内所有属于待测主体的支持视为一个整体目标。
2. 相邻结构之间的内部白色间隙可以被整体外包络跨过。
3. 不允许把单根细支、内部暗线、交叉线或纹理宽度作为正式 distance。
4. 正式 A/B 必须来自同一有效扫描行的整体最外侧支持。
5. 外部 speck、小黑点和灰尘不得扩张整体外包络。
6. 夹具、连接丝、支撑丝、窄尾和焊点不得决定正式 A/B；应优先通过窄测量带避开。
7. 窄测量带用于减少带外噪声，但仍必须执行连通域、最小支持量、跳变和 INVALID 判定。
```

## 8. ROI 规则

### 8.1 ROI 类型

```text
检测位置数量：最少 1 个，最多 6 个；默认 1 个。
每个检测位置拥有独立 rotated ROI；未启用位置保留配置，但不检测、不生成正式曲线、不导出正式数据。
ROI 类型：rotated ROI。
产品语义：可旋转窄测量带，而不是覆盖大面积主体的检测框。
新建 ROI 默认高度：8 px（measurement coordinates）。
最小交互高度：8 px；不得保存为零高度几何线。
ROI 操作方式：操作者在 Web UI 上用鼠标拖拽。
ROI 角度：通过拖拽产生，不要求手动输入角度。
ROI 范围：沿正式 A/B 测量方向穿过有效主体，并避开夹具、连接丝和其他非测量结构。
```

### 8.2 检测位置与运行锁定

```text
用户可在测试开始前添加、删除、启用、禁用、重命名检测位置，并选择当前编辑位置。
删除后显示顺序可重排，但 region_id 和 color 对仍存位置保持稳定。
至少保留 1 个位置且至少 1 个位置启用；最多配置 6 个位置。
测试开始后，本次 run 的 regions 快照锁定，运行中不可新增、删除、启用、禁用或修改 ROI。
同一帧图像只采集一次、温度只读取一次；所有启用位置共享该帧和温度，并分别执行检测。
每个位置独立维护检测结果、异常点过滤状态、正式 temperature-distance 曲线和 AFAS 分析结果。
```

### 8.3 ROI 坐标系统

正式需求写法：

> 系统必须使用统一、稳定、可复现的 measurement coordinates 进行正式测量。默认 measurement coordinates 为原始图像 pixel 坐标。前端可以缩放显示图像，但缩放只影响显示，不影响正式 ROI、A/B、distance 计算。

也就是说：

```text
操作者看到的是浏览器显示图。
系统内部保存的是 measurement coordinates 下的 ROI。
A/B 点和 distance_px 都在 measurement coordinates 中计算。
```

这样做的原因不是因为 Af 测试必须使用原始坐标，而是为了保证：

```text
同一组数据，
同一套 ROI，
同一套参数，
在不同电脑、不同浏览器窗口、不同缩放比例下，
得到完全一致的 distance 曲线。
```

### 8.3 ROI 与参数联动

当用户修改以下任一内容时，应重新检测当前 ROI 内物体：

```text
ROI
detector 类型
max/min-width mode
threshold
morphology 参数
jump limit
其他 detector 参数
```

### 8.4 Run 配置快照

每次正式 run 开始时，系统必须保存当时的：

```text
ROI
detector 类型
width mode
全部 detector 参数
温控参数
相机参数
软件配置
```

后续用户修改 ROI 或参数，不覆盖旧 run。

## 9. Measurement Coordinates 与趋势曲线

G3 的业务目标是得到：

```text
temperature - distance_px 曲线
```

而不是得到绝对物理尺寸。

因此：

```text
distance_px 可以是相对像素值。
不需要 mm 换算。
不需要标定板。
不需要 pixel-to-mm calibration。
```

但必须保证：

```text
distance_px 的坐标尺度在一次 run 内保持一致。
同一数据集重复分析结果必须一致。
同一帧不能因为前端缩放不同而得到不同 distance。
```

所以系统内部默认使用原始图像 pixel 坐标作为 measurement coordinates。

## 10. A/B 稳定性策略

G3 不简单使用“最大跳动阈值”限制真实变化。

因为真实测试中，待测物体可能真的在变形，A/B 位置和 distance 都可能发生变化。

真正需要解决的是：

```text
多个候选位置宽度相同或非常接近时，
A/B 点在几个候选位置之间来回跳。
```

### 10.1 候选选择规则

每帧检测时保存两类候选：

```text
raw_best_candidate
selected_candidate
```

含义：

```text
raw_best_candidate：
    本帧纯按宽度最大原则得到的候选。

selected_candidate：
    经过时间连续性稳定策略后，正式用于 distance 曲线的候选。
```

### 10.2 Tie-break 策略

当多个候选宽度接近时：

```text
1. 找出本帧所有合法候选。
2. 找出 raw_best_width。
3. 若多个候选与 raw_best_width 的差值 <= tie_width_epsilon_px，则视为宽度等价。
4. 在宽度等价候选中，优先选择离上一帧 selected_candidate 最近的候选。
5. 只有当新候选明显更宽，或连续 N 帧更优，才允许切换位置。
```

### 10.3 Invalid 优先原则

G3 遇到异常帧时：

```text
宁可输出 INVALID，
也不要输出看似正常但实际错误的 A/B。
```

异常情况包括：

```text
外包络不可信
候选跳变过大
目标连通性异常
A/B 点落在内部结构
A/B 点落在外部 speck
A/B 点落在夹具或连接丝
ROI 内目标缺失
质量评分不足
温度同步不可用于 Af 分析
```

## 12. 温度同步需求

G3 需要真实温控仪 / PLC。

运行模式包括：

```text
Offline playback
Live offline run
Real camera run
```

都需要能把以下数据对应起来：

```text
frame
timestamp
temperature
distance
```

### 12.1 温度同步目标

```text
图像帧时间戳与温度时间戳误差目标：<= 10 ms。
```

每帧保存：

```text
frame_timestamp_ms
temperature_timestamp_ms
temperature_celsius
temperature_delta_ms
temperature_source
temperature_sampled_this_frame
temperature_sync_status
```

### 12.2 温度状态

```text
TEMP_SYNC_OK：
    |frame_timestamp_ms - temperature_timestamp_ms| <= 10 ms。

TEMP_SYNC_INTERPOLATED：
    使用前后温度采样点插值得到该帧温度。

TEMP_SYNC_STALE：
    温度值复用了旧采样，且时间误差 > 10 ms。

TEMP_SYNC_MISSING：
    没有温度数据。
```

### 12.3 温度异常帧处理

已确认采用 A + C：

```text
A/B 检测结果仍保存。
Af 计算和 temperature-distance 曲线只使用 TEMP_SYNC_OK 或 TEMP_SYNC_INTERPOLATED 的点。
```

不因为温度 stale 就丢弃图像检测结果，但 stale 点不能进入正式 Af 分析。

## 13. 运行模式

G3 支持以下运行模式。

| 模式 | 是否需要 | 说明 |
|---|---|---|
| Offline playback | 是 | 读取真实离线帧，逐帧查看 |

### 13.1 建议开发顺序

```text
1. Offline playback
2. Live offline run
3. Re-analysis
4. Real camera preview
5. Real camera run
6. Analysis / Export
```

## 20. Re-analysis 规则

G3 支持 re-analysis。

规则：

```text
1. 历史 run 的原始输入和原始结果不覆盖。
2. 使用新 ROI、新 detector 或新参数重新分析时，生成新的 analysis version。
3. 每个 analysis version 保存自己的配置快照。
4. 同一数据、同一配置、同一代码版本，重复运行结果必须完全一致。
```

## 21. 验收标准

第一阶段验收重点如下：

```text
1. 同一 offline dataset 重复运行，结果完全一致。
2. 新建测量统一为 WHOLE_ENVELOPE + ContrastWidestSpanDetector + max_width，并能输出 distance_px。
3. A/B 点必须落在整体外包络上。
4. A/B 点不能跳到内部缝隙、内部暗线、纹理、单根细支或外部 speck。
5. 多结构目标必须作为整体外包络测量，不能测单根线。
6. 前端缩放不影响正式 distance 结果。
7. 新建 ROI 默认为 8 px 非零窄测量带，修改、移动或旋转后当前帧可立即重新检测。
8. 异常帧输出 INVALID，不输出错误 A/B。
9. rejected candidate 必须有 rejected_reason。
10. Offline playback 能显示 frame、temperature、A/B、distance、overlay。
11. Live offline run 能按 5-10 fps 输出结果。
12. Real camera preview 可启动。
13. Real camera run 可保存原始帧和结果。
14. temperature-distance 曲线只使用 TEMP_SYNC_OK 或 TEMP_SYNC_INTERPOLATED 的点。
15. 可导出 CSV、JSON、PNG 曲线图。
```

## 23. 当前已锁定的关键决策

```text
当前业务模型 = WHOLE_ENVELOPE，不再划分 A/C/D 类。
当前 detector = ContrastWidestSpanDetector；旧 detector 仅保留历史兼容。
width mode = 固定 max_width。
A/B = 窄测量带内同一有效扫描行上整体外包络的两个最外侧接触点。
检测位置 = 默认 1 个、最少 1 个、最多 6 个；每个位置一个 rotated ROI。
region_1 = 旧单 ROI 兼容位置；顶层 roi / DetectionResult / AnalysisResult 字段镜像第一个启用位置。
新建 ROI = 默认高度 8 px 的非零可旋转窄测量带。
ROI 坐标 = 统一 measurement coordinates，默认原图 pixel。
distance = pixel only。
核心目标 = temperature-distance trend。
外包络 = 可跨内部缝隙，但不是纯凸包。
像素判定 = 使用窄测量带背景中位数与亮暗对比阈值形成目标支持。
内部缝隙/纹理/暗线 = 忽略。
多细支 = 整体目标。
外部 speck = 排除，不能识别为目标。
异常帧 = INVALID 优先，不输出错误 A/B。
温度同步 >10ms = A/B 保存，Af 曲线只用 OK/interpolated 点。
导出 = CSV / JSON / PNG。
```

## 26. 术语表

| 术语 | 含义 |
|---|---|
| Measurement Position / MeasurementRegion | 一套稳定 `region_id`、显示顺序、名称、启用状态、颜色和 rotated ROI；每次测量允许 1–6 个。 |
| ROI / 窄测量带 | 某一检测位置的非零高度 rotated ROI；局部宽度轴为 A/B 测量轴，新建默认高度 8 px，所有坐标均使用 measurement coordinates。 |
| measurement coordinates | G3 正式计算使用的统一坐标系，默认等于原始图像 pixel 坐标。 |
| A/B 点 | 窄测量带内同一有效扫描行上整体外包络的两个最外侧接触点。 |
| distance_px | A/B 两点之间的欧氏像素距离。 |
| outer envelope / 整体外包络 | 跨过内部缝隙但不包含明显外部空白的目标整体边界。 |
| raw_best_candidate | 本帧纯按宽度最大原则得到的候选。 |
| selected_candidate | 经过时间连续性稳定策略后用于正式曲线的候选。 |
| TEMP_SYNC_OK | 温度与图像时间戳误差 <= 10ms。 |
| TEMP_SYNC_INTERPOLATED | 用前后温度采样点插值得到的温度。 |
| TEMP_SYNC_STALE | 温度复用了旧采样且时间误差 >10ms。 |
| INVALID | 当前帧检测不可作为正式结果。 |

## 27. 结论

G3 的核心需求可以总结为：

> 系统通过 Web UI 放置一个默认 8 px 高、可旋转的非零窄测量带，在统一 measurement coordinates 中依据像素亮暗对比识别待测物体整体外包络，并提取同一有效扫描行上的 max_width A/B 点，持续输出 distance_px 与 temperature 对应关系。当前产品只有 WHOLE_ENVELOPE 统一模型，不再区分 A/C/D 类。内部缝隙、纹理、暗线、单根细支、外部 speck、夹具和非测量结构不能成为正式 A/B。异常帧优先输出 INVALID；temperature-distance 曲线只使用温度同步 OK 或可插值的数据点。
