## 1. 测试分层

G3 测试按风险和可复现性分为 6 层。

| 层级 | 名称 | 目的 | 适用内容 | 是否可自动化 |
|---|---|---|---|---|
| T0 | 静态一致性检查 | 防止结构、路径、需求约束被破坏 | 目录、配置、硬编码路径、枚举、schema 字段 | 是 |
| T1 | 单元测试 | 验证纯函数和数据结构 | ROI 坐标转换、温度同步、candidate 选择、序列化 | 是 |
| T2 | 服务/API 集成测试 | 验证 backend 服务边界 | dataset loader、playback、run manifest、analysis、export | 是 |
| T3 | 算法回归测试 | 验证统一整体外包络和 A/B 规则 | synthetic fixtures、两组 Golden 关键帧、INVALID 场景 | 部分自动化 |
| T4 | 真实浏览器流程复测 | 验证 UI 与后端流程一致 | Setup、Playback、Run、Analysis/Export、overlay、下载 | 是，必须保留证据 |
| T5 | 硬件/人工确认 | 验证真实相机和人工视觉判断 | Hik MVS、真实温控、弱边缘外包络人工复核 | 部分手动 |

每个 milestone 至少应有 T0-T2 中的对应检查。涉及 ROI、overlay、Playback、Run、Analysis、Export 的 milestone 必须执行 T4。

## 2. 测试数据原则

### 2.1 Golden dataset

第一阶段固定使用以下 dataset id，不在代码、API 测试、前端测试或浏览器复测中硬编码本机绝对路径。

| Dataset ID | 当前模型 | 默认 detector | width mode | 必测阶段 |
|---|---|---|---|---|
| `golden_a_20260522_dev_lab` | `WHOLE_ENVELOPE` | `ContrastWidestSpanDetector` | `max_width` | M0、M3、M4、M5、M6、M7、M9 |
| `golden_c_20260529_dev_lab` | `WHOLE_ENVELOPE` | `ContrastWidestSpanDetector` | `max_width` | M0、M3、M4、M5、M6、M7、M9 |

### 2.2 Synthetic fixtures

算法和边界条件不能只依赖真实素材。建议补充小型 synthetic fixtures：

| Fixture 类型 | 用途 |
|---|---|
| 简单矩形/旋转矩形 mask | 验证 max-width、ROI 坐标、A/B 欧氏距离 |
| 带内部空洞的目标 | 验证内部白色缝隙不成为正式 A/B |
| 多根细线整体 | 验证统一整体外包络，不测单根线 |
| 8 px 窄测量带 | 验证默认带宽、最小非零高度和同一扫描行 A/B |
| 外部 speck | 验证 speck 不进入 target/envelope |
| 目标缺失/低置信度 | 验证 INVALID 优先 |
| 宽度接近的多候选序列 | 验证 tie-break 和 selected_candidate 稳定性 |
| 温度稀疏/缺失/超时序列 | 验证 OK、INTERPOLATED、STALE、MISSING |

### 2.3 Evidence 目录建议

自动化和浏览器复测证据建议保存在：

```text
output/test_evidence/<date>/<test_id>/
output/playwright/<date>/<test_id>/
output/exports/<run_id>/
```

`problem.md` 中只记录摘要和证据路径，不直接粘贴大段日志。

## 3. Milestone 测试矩阵

### M0：Golden Dataset 和验收基准

| 项目 | 测试方法 |
|---|---|
| 目标 | 证明两组历史命名真实离线素材可被 registry 解析，并能作为后续回归和浏览器复测基准。 |
| 覆盖需求 | dataset registry、dataset id 调用、manifest/temperature/frame 可访问、默认 detector 映射、禁止源码硬编码本机路径。 |
| T0 静态检查 | 检查 `configs/local/offline_datasets.local.json` 存在；检查 backend/frontend/scripts 中没有硬编码本机素材绝对路径；检查 dataset id 与注册表文档一致。 |
| T1 单元测试 | `load_dataset_registry()` 解析 schema；缺失字段、重复 id、错误 detector、错误 width mode 应报清晰错误。 |
| T2 集成测试 | `list_offline_datasets()` 返回两组当前统一模型与 legacy_profile；`resolve_dataset()` 返回 manifest、temperature、frames；`load_first_frame()`、`load_last_frame()` 可读取 shape/dtype。 |
| T4 浏览器复测 | Setup/Playback 页面列出两组 dataset id；分别加载 first frame 和 last frame；当前统一测量原则与窄测量带正确显示。 |
| 数据 | `golden_a_20260522_dev_lab`、`golden_c_20260529_dev_lab`。 |
| 通过标准 | 两组数据均可解析和预览；缺文件或路径不可访问必须登记 `problem.md`；不得因为单元测试通过就跳过浏览器复测。 |

### M2：核心数据模型

| 项目 | 测试方法 |
|---|---|
| 目标 | 先把正式数据契约锁住，避免 UI、算法和导出各自发明字段。 |
| 覆盖需求 | `RotatedROI`、`MeasurementCoordinates`、`MeasurementDefinition`、`DetectorConfig`、`FrameRecord`、`TemperatureRecord`、`TemperatureSyncStatus`、`ABPoint`、`DetectionCandidate`、`DetectionResult`、`RunManifest`、`AnalysisResult`、`ExportArtifact`。 |
| T0 静态检查 | 枚举值必须覆盖 `VALID`/`INVALID`、`TEMP_SYNC_OK`/`INTERPOLATED`/`STALE`/`MISSING`；当前默认必须是 `WHOLE_ENVELOPE + ContrastWidestSpanDetector + max_width`；旧枚举只用于兼容。 |
| T1 单元测试 | JSON round-trip；必填字段缺失报错；ROI rotated rectangle 支持浮点 center/width/height/angle；DetectionResult 可表达无 A/B 的 INVALID。 |
| T2 集成测试 | MeasurementDefinition 与 RunManifest 可被 storage 写入和读取；AnalysisResult 能引用 detection results 和温度状态。 |
| T4 浏览器复测 | 通常不强制，除非模型变更已经暴露在 Setup/Run/Analysis 页面。 |
| 数据 | small JSON fixtures；可加入 golden dataset 的 manifest 片段。 |
| 通过标准 | schema 与 docs/data 草案一致；前端不得用显示坐标字段替代 measurement coordinates。 |

### M3：Offline Playback + ROI

| 项目 | 测试方法 |
|---|---|
| 目标 | 离线帧可加载、显示、设置 rotated ROI，并在 measurement coordinates 中 probe 当前帧。 |
| 覆盖需求 | Offline playback、frame preview、8 px 默认窄测量带拖拽/缩放/旋转、ROI 保存、当前帧 probe、A/B overlay、quality/status、前端缩放不影响正式 distance。 |
| T0 静态检查 | 前端 ROI 提交 payload 必须包含 measurement coordinates；backend API 不接受只含 display coordinates 的正式测量请求。 |
| T1 单元测试 | display-to-measurement 坐标映射；measurement-to-display overlay 映射；窗口缩放、device pixel ratio、canvas fit/downsample 场景 round-trip。 |
| T2 集成测试 | 通过 dataset id 加载 frame；保存 ROI；调用 probe API；返回 DetectionResult、quality/status、overlay artifact 或 overlay geometry。 |
| T3 算法回归 | 当前阶段 detector 可为占位或原型，但 INVALID/quality/status 必须结构完整；不得输出不符合 schema 的假正常结果。 |
| T4 浏览器复测 | 在 100%、125%/150% 缩放和不同窗口大小下，对同一帧、同一 ROI、同一参数 probe，正式 `distance_px` 必须一致；overlay 与图像对齐。 |
| 数据 | 两组 Golden dataset 的 first frame、last frame；必要时加 synthetic ROI mapping fixture。 |
| 通过标准 | ROI 修改后可立即重新检测当前帧；浏览器缩放只影响显示，不影响正式结果。 |

### M4：统一整体外包络 Detector

| 项目 | 测试方法 |
|---|---|
| 目标 | 实现 WHOLE_ENVELOPE 窄测量带 max_width A/B 检测。 |
| 覆盖需求 | `ContrastWidestSpanDetector`、contrast mask、同一扫描行 outer span、raw_best_candidate、selected_candidate、ab_points、distance_px、quality、rejected_reason、debug_overlay。 |
| T0 静态检查 | 当前 detector 和 width mode 固定；新建 ROI 默认/最小高度为 8 px；当前 UI 不暴露 legacy 分类或 detector；debug 字段名与数据结构一致。 |
| T1 单元测试 | synthetic 窄带上验证 A/B 在同一扫描行整体最外侧；内部空隙/暗线不产生正式边界；夹具/连接丝/窄尾与 speck 被过滤；目标缺失输出 INVALID。 |
| T2 集成测试 | backend probe/run detector 输出完整 DetectionResult；VALID 结果必须有 A/B 和 distance；INVALID 结果不得带正式 distance。 |
| T3 算法回归 | 对两组 Golden dataset 的关键帧运行统一 detector，保存 overlay、contrast mask、candidate、quality；人工复核 A/B 是否在同一扫描行整体左右外侧。 |
| T4 浏览器复测 | Setup/Playback 中查看两组 overlay；确认无分类选择、默认 8 px 窄带可操作，诊断面板显示 raw_best_candidate、selected_candidate、rejected_reason。 |
| 数据 | `golden_a_20260522_dev_lab`、`golden_c_20260529_dev_lab`；synthetic mesh-with-holes、mesh-with-clamp、speck、bundle fixtures。 |
| 通过标准 | 内部空隙/暗线/交叉线不成为边界，夹子/连接丝/窄尾不决定 max-width，不测单根线，外部 speck 不成为目标，异常帧 INVALID。 |

### M5：A/B 稳定策略

| 项目 | 测试方法 |
|---|---|
| 目标 | 解决多个候选宽度接近时 selected_candidate 在帧间跳动的问题。 |
| 覆盖需求 | raw_best_candidate、selected_candidate、tie_width_epsilon_px、previous_candidate_preference、switch_after_n_frames、jump_rejection、invalid instead of wrong AB。 |
| T0 静态检查 | DetectorConfig 必须暴露稳定策略参数；rejected candidate 必须可记录 rejected_reason。 |
| T1 单元测试 | 构造宽度等价候选序列，验证优先沿用上一帧；构造连续 N 帧更优，验证允许切换；构造大跳变低质量，验证 INVALID。 |
| T2 集成测试 | Live/offline sequence service 能把上一帧 selected_candidate 传给下一帧；run manifest 保存 raw_best 和 selected。 |
| T3 算法回归 | 对两组 Golden 连续帧运行，统计 selected_candidate 帧间跳变、INVALID、rejected_reason；人工复核跳变点 overlay。 |
| T4 浏览器复测 | Live offline run 页面连续播放，观察 A/B overlay 不在等宽候选之间来回跳；诊断面板显示 tie-break 和 rejected reason。 |
| 数据 | 两组 Golden 连续帧；synthetic equal-width candidate sequence。 |
| 通过标准 | 等宽或近等宽候选优先连续；只有明显更优或连续 N 帧更优才切换；错误候选被 rejected。 |

### M6：温度同步和曲线

| 项目 | 测试方法 |
|---|---|
| 目标 | 每帧保存温度同步状态，并正确生成 distance-time、temperature-time、temperature-distance 曲线。 |
| 覆盖需求 | `TEMP_SYNC_OK`、`TEMP_SYNC_INTERPOLATED`、`TEMP_SYNC_STALE`、`TEMP_SYNC_MISSING`；A/B 检测结果始终保存；temperature-distance/Af 只使用 OK 或 INTERPOLATED。 |
| T0 静态检查 | 枚举名称和导出字段统一；曲线服务不得直接丢弃 stale/missing 帧的 DetectionResult。 |
| T1 单元测试 | 误差 <=10ms 为 OK；前后采样可插值为 INTERPOLATED；旧采样 >10ms 为 STALE；无温度为 MISSING；边界值 10ms 必测。 |
| T2 集成测试 | AnalysisResult 同时保留全部 per-frame records 和正式曲线 filtered points；CSV/JSON 包含 temperature_delta_ms 和 temperature_sync_status。 |
| T3 算法/数据回归 | 用 golden temperature.csv 和 synthetic sparse temperature fixture 验证状态分布和曲线点数。 |
| T4 浏览器复测 | Analysis 页面显示三类曲线；temperature-distance 曲线不包含 STALE/MISSING 点；导出与 UI 点数一致。 |
| 数据 | 两组 Golden temperature.csv；synthetic OK/interpolated/stale/missing fixtures。 |
| 通过标准 | STALE/MISSING 不进入正式 temperature-distance/Af 曲线，但对应帧检测结果仍可在明细和导出中追踪。 |

### M7：Live Offline Run

| 项目 | 测试方法 |
|---|---|
| 目标 | 把离线 frames 当作相机流，以 5-10 fps 完成实时检测、显示、曲线和保存。 |
| 覆盖需求 | start/stop、逐帧检测、实时 ROI/A/B/distance/temperature、实时曲线、保存 run result、回放该 run。 |
| T0 静态检查 | Run 配置快照必须包含 ROI、detector、width mode、detector 参数、温控参数、软件配置；不得运行后覆盖旧 run。 |
| T1 单元测试 | run state machine：idle/running/stopping/stopped/error；stop 后不继续写入帧；重复 start 行为明确。 |
| T2 集成测试 | 使用 dataset id 启动 live offline run；保存 run manifest、frame records、detection results、artifact paths；回放该 run。 |
| T3 回归测试 | 同一 dataset、同一 ROI、同一参数重复 run，结果应可比较且一致；如存在时间调度差异，正式检测结果仍应确定。 |
| T4 浏览器复测 | Run 页面启动、停止、实时显示 A/B/distance/temperature/曲线；保存后 Playback/Analysis 可打开该 run。 |
| 数据 | 两组 Golden dataset；短帧数 smoke 和较长片段回归各一组。 |
| 通过标准 | 运行过程中 UI 和保存结果一致；run manifest 可追溯；浏览器流程通过。 |

### M8：Real Camera Preview / Run

| 项目 | 测试方法 |
|---|---|
| 目标 | 接入 Hik MVS / 海康 GigE，同时保证无相机环境下 offline/playback 不受影响。 |
| 覆盖需求 | SDK lazy import、无相机 backend 可启动、SDK 缺失错误清晰、Mono8 优先、保存原始帧、camera_meta、real camera preview/run。 |
| T0 静态检查 | 普通 import 路径不得 import Hik MVS SDK；camera adapter 必须隔离在 real camera 调用路径。 |
| T1 单元测试 | mock camera source 输出 FrameRecord；SDK 缺失时返回结构化错误；camera_meta 字段可序列化。 |
| T2 集成测试 | 无 SDK/无相机环境下 backend 启动、Offline playback、Live offline run、Re-analysis 可用；real camera endpoint 返回清晰错误。 |
| T4 浏览器复测 | 无相机环境：Device/Run 页面错误提示清晰，offline 功能不受影响。有相机环境：preview 可显示帧，run 可保存 manifest。 |
| T5 硬件测试 | 连接 Hik MVS/GigE 相机，验证 Mono8、frame timestamp、camera_meta、目标 5-10 fps 处理链路。 |
| 数据 | 无相机环境必测；真实相机环境有硬件时补测。 |
| 通过标准 | 没有相机或 SDK 时不能破坏 M0/M3/M7；有相机时保存原始帧和 camera metadata。 |

| 目标 | 导出第一阶段 CSV、JSON、PNG 曲线图、ROI 截图、A/B overlay、参数表。 |

| 需求 ID | 需求摘要 | 主要阶段 | 推荐测试方法 |

| R-01 | 当前模型固定为 `WHOLE_ENVELOPE + ContrastWidestSpanDetector + max_width`，旧值仅兼容 | M2、M4、M9 | T0 检查 default config/UI；T1 schema 兼容测试；T3 两组 Golden 回归 |

## 6. Milestone 完成判定

一个 milestone 只能在以下条件同时满足时标记完成：

```text
1. 该 milestone 的 T0-T2 检查已执行并通过，或明确登记阻塞原因。
2. 如果涉及 UI/流程/overlay/曲线/导出，T4 真实浏览器复测已通过。
3. 如果涉及整体外包络 detector 或窄测量带，必须使用两组 Golden dataset 做过回归和 overlay 复核。
4. 如果涉及真实相机，区分“无相机环境已通过”和“有相机硬件待补测”。
5. 所有发现的问题已登记到 problem.md。
6. 修复类问题只有在真实浏览器复测通过后，才能标为 RESOLVED_BROWSER_VERIFIED。
7. 输出结果、截图、日志或导出 artifact 有可追踪路径。
```
